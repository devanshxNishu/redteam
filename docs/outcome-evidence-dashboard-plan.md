# Controlled evidence dashboard plan

Next slice after 0.22.0: web selection, registration, catalog, and checked detail for the existing controlled outcome evidence contract. This adds no new outcome semantics, source kind, intervention execution, report-export kind, participant data, or prediction claim.

## Workflow

Add a Reviews card for recent permitted evidence links. From a checked frozen plan, offer an explicit link-evidence form only for its controlled browser-finding origin. Show the exact baseline job/finding/requirement, the frozen window, and the fixed unadjudicated limits. Require the operator to choose a distinct saved comparable candidate comparison for that baseline; show IDs and observed verdict. Filter available comparisons through current plan/comparison/review catalogs and completed source jobs, while the server retains full time/lineage/integrity checks. Accept only the optional bounded supplied note and selected comparison ID; pin the displayed plan ID. Do not choose an outcome, infer hypothesis success, relabel an early/late capture, or silently substitute another source.

Preserve the selected typed IDs and note across refresh. Remove unselected withdrawn/missing source labels; close when the selected plan/comparison/source is unavailable. Show why incomplete catalog knowledge prevents a selection. Lock controls while creation is pending. A 400 can follow committed publication: show the server's inspect-records guidance and provide deliberate navigation to the catalog, without retry, undo, reduced selection, plan rewrite, or action promotion.

Open only whitelisted checked API detail. Render supplied notes and all record text through literal text/value nodes. Show fixed assessment and scope before long hashes. Show actual comparison verdict, local time alignment, plan/comparison/action IDs and historical revision, checked artifact hash/size/type metadata, and limits. No artifact or arbitrary file download is available. Optional collapsed literal JSON must not render HTML/Markdown. No private source pin or directory should enter the client payload.

## Lifecycle and source boundaries

Add the protected evidence catalog to the existing all-or-nothing metadata refresh. Extend current-parent/source filtering rather than trust one stale response. Evidence links require the exact known plan, comparison, and completed baseline/candidate jobs; absent parents outside recent windows remain unavailable. Current controlled fixture sources use no target grant; do not invent expiry/consent properties. Full detail refresh remains responsible for saved-file and source integrity, local-clock changes, and historical action checks. Failed metadata refresh clears managed content/catalogs.

Use the shared dialog generation, abort, expected-close, focus/visibility refresh, safe reset, and late-response guards. An old initial/detail/create response cannot reopen a closed/restricted view or replace a newer dialog. Keep only primitive selected IDs and form drafts in current-view memory; do not add local/session storage or a global full-report cache. Preserve existing action, plan, comparison, export, actor, image, Blob, and permission behavior.

## Meaningful verification

Verify an actual baseline finding/action, genuinely frozen plan, later actual candidate/comparison, and successful web registration, with exact source IDs, supplied note, fixed labels, checked source/link bytes, and unchanged plan/action/jobs/actors. Verify refresh preservation, empty/invalid selection, literal hostile/long text, desktop and 390 px layout, known missing/limited sources, saved artifact tamper, normal idle-poll closure/catalog clearing, late initial/detail/committed-create responses, mixed stale/current catalogs, failed refresh, no duplicate registration, and no persistent browser storage. Author negative software fixtures explicitly; do not describe them as human research or prospective validation. Repack/install a new final prefix, visually inspect relevant screenshots, verify all archive bytes/whitelist, and normally push the verified source commit to private GitHub.

Independent human outcome tracking, blinded adjudication, empirical stakeholder validity, live provider verification, external app isolation, C03 paid demand, and broader specialist hierarchy remain separate gates.
