# Controlled outcome evidence linking plan

Next narrow slice after 0.20.0: prepare U06 by linking a frozen supplied plan to a later checked controlled-signup comparison. This is evidence registration, not independent outcome adjudication, participant collection, or a completed U06 release gate. It requires no external credentials, recruitment, or expanded actor hierarchy.

## Allowed workflow

Start with an actual saved browser finding and its tracked action. Freeze a supplied experiment plan against that action before its future local-clock window. Run a separate later controlled candidate review. Create the existing checked baseline/candidate comparison. Register an immutable evidence link with exactly a plan ID, comparison ID, and optional bounded supplied note, under a strict versioned JSON input. No review, intervention, model, or source test is run by registration.

Only a plan whose pinned action origin is the exact baseline review finding can use this first slice. The compared requirement must be the source finding's requirement. A source-note action, a different baseline, not-comparable comparison, reused baseline/candidate identity, invalid provenance, or changed source bytes is unavailable. The baseline must predate plan freeze; all candidate executions must start within the frozen window and finish within it, with consistent local timestamps no later than registration. Late or early captures must not be silently relabeled as matching the plan.

Read and pin the full saved plan, checked historical action/source, comparison, and baseline/candidate evidence. Recheck current permission, identities, immutable hashes, and relevant time relations around publication and inside the synchronous catalog insert guard. Use existing private bounded-file and first-valid-publication patterns. Store the exact input, minimal source pins, and checked report in a private evidence directory. Atomically reject duplicate plan/comparison registration and audit successful insertion. Preserve orphan bytes after uncertain publication; do not adopt, replace, retry, clean, or upgrade them automatically.

Keep the frozen plan, action revisions, comparison, jobs, actors, grants, and all original artifacts unchanged. Later legitimate action declarations may not rewrite an old link. Retrieval must verify the immutable source projections and current permissions, rather than trust a label or just the absence of findings. List entries are minimal, explicitly unverified catalog metadata; full reads check all saved bytes and guards.

## Fixed conclusions and exclusions

The record may state that specified controlled browser evidence was linked and that local timestamps meet the recorded relation. It must copy the factual comparison verdict without converting it into a plan success or population effect. Fix independent review, protocol/semantic review, sample adequacy, hypothesis resolution, and causal attribution to not established/not assessed. A supplied hypothesis or target sample count is not adjudicated by a requirement assertion.

The plan's original uncollected/unexecuted labels remain unchanged; registration executes no intervention and does not prove the planned intervention happened. No action receives automatic completed/verified status. The record is scoped to the software fixture, not a researched consumer/investor behavior, purchase, funding, customer demand, human evaluation, or commercial validation. Local clocks/operator/filesystem/metadata are trusted and are not external prospective registration. Independent outcome collection, blinded adjudication, held-out human evaluation, and protocol approval remain open.

Initial access is terminal only, with strict register/list/show commands. No API, dashboard, export-kind expansion, arbitrary file upload, participant data, arbitrary outcome claims, or broad specialist scheduling is enabled in this slice. Those can follow separate contracts after the local lineage is verified.

## Meaningful verification

Use a real controlled baseline finding, genuinely frozen plan, and separately executed candidate for the positive installed path; keep software fixture and human validity distinct. Test early/late/reused/mismatched sources, inconsistent source timestamps, changed study/requirement, not-comparable results, altered plan/action history/comparison/evidence/artifact bytes, missing/unsafe directories, current permissions, later legitimate action updates, strict input/getters, duplicate concurrent insertion, insertion-time access/source changes, atomic audit, orphan preservation, and no state promotion. Full-suite regression, compiled package installation, exact archive whitelist/bytes, and normal verified GitHub push remain release requirements.
