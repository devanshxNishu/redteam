# Bounded analytical review: next implementation

This is the I04 plan after 0.27.0; 0.28.0 implements I04a only. See [the packet/check contract](analytical-review.md). Intake works through web, terminal and protected API. A brief and its fixed question preview are not a completed analytical review. Live analysis, a multi-agent roundtable, researched consumer behavior and investor prediction are not enabled by this document.

## Product result

The next useful result is a concise analysis of one supplied idea or app brief. It should identify assumptions, evidence gaps, possible internal conflicts and useful next checks. Product, engineering, buyer, commercial, investor-preparation and verification are analytical lenses. They are not researched people or simulated purchases/investments.

Every material concern needs a precise basis in the supplied brief and an explicit limit. External facts require a separately checked source path; an unopened reference is not such a source. The first analytical path can work with brief claims alone, but all conclusions must retain that restriction. It cannot produce a verified defect or claim actual app testing from a URL description.

## Ordered slices

1. **I04a — packet and output contract (implemented in 0.28.0).** Derive a bounded deterministic packet from a fully checked saved brief. Give each supplied non-null field or list entry a stable local reference, exact text and hash. Preserve explicit unknowns, assumptions and unopened/unverified evidence labels. Exclude private paths/catalogs/sessions/credentials automatically; supplied text can still contain private information. Add terminal packet inspection. Define and test strict bounded analytical output with exact packet/brief identity and resolvable field citations. Run no model or tool.
2. **I04b — one bounded analyst.** Use an explicitly configured provider/processing choice and the existing durable budget, fenced ownership and immutable publication patterns after inspecting their fit. A brief alone does not dispatch a model or authorize new target access. Supply the packet as untrusted data, with no shell/browser/payment/delegation tool. Use one bounded attempt; uncertain dispatch/spend and interrupted work require factual recovery, not automatic replay. Verify with fake transport before a separately recorded live run. Missing credentials/processing choice must give a clear unavailable state.
3. **I04c — review gate and report.** Show analytical concerns, their supplied basis, proposed checks, contradictions and unknowns. Mark structural/reference checks separately from semantic review. Keep an unreviewed state until an explicit permitted review occurs. Add terminal/API/web inspection with current source/publication checks, literal content, managed-view lifecycle and no automatic action/experiment promotion. Record measured pilot usefulness before claiming commercial validity.

These are narrow work units, not a broad specialist hierarchy. C03 paid concierge demand, shared resource budgets, external worker isolation and research/evaluation remain prerequisites for the wider roundtable.

## Packet boundary

The packet must bind the exact brief ID, policy, publication hash and normalized input hash. References identify supplied fields, not external truth. An app URL or evidence reference remains unopened. Country and language remain context; they do not assign a psychological profile or population weight.

Initially include only the selected brief. Do not attach unrelated local signup captures or source snapshots to a claimed app automatically. Actual app evidence needs an established target/build/journey/requirement association and current access before it can support a claim about that app. The existing local fixture result is not proof about another app.

Keep byte, field-count, citation-count and output limits explicit. A byte limit is not a token/cost/time budget; the provider path needs its own measured reservation/usage rules. Do not split a large brief silently or remove fields without recording incomplete coverage.

## Output contract

Proposed output has a fixed analytical type and exact packet identity. Each concern contains a stable ID, allowed track, type (`assumption_risk`, `evidence_gap`, or `consistency_question`), bounded statement, cited supplied-field references, why it matters, priority with reason, and a proposed next check. An evidence gap can cite an explicit unknown. A proposed protocol/sample is unreviewed, not an approved experiment.

Use fixed labels: analytical, unreviewed, supplied basis unverified, app execution not performed, stakeholder decision not performed. Do not add numeric confidence, a universal startup score, purchase demand, population likelihood, funding probability, verified defect or an actual buyer/investor commitment. Unknown or unsupported citation IDs must fail validation. A citation match establishes that the supplied text exists; it does not establish that the text or generated inference is correct.

Strict schema validation cannot detect every unsupported prediction inside free text. Do not claim otherwise. Separate semantic review and adversarial evaluation are necessary. Even a reviewed analytical objection does not become a validated behavioral prediction. Research-grounded actor scenarios and held-out prediction keep their independent gates.

## Verification

Use authored fixtures labeled as software checks. Test idea/app packets, stable identity/field order, exact supplied and null/unknown provenance, UTF-8/field/output bounds, no implicit references, invalid paths/citations/subjects/claims, getters/serializers, changed own/source/catalog bytes, unavailable source, unsafe files, literal long text and terminal installed behavior. Assert zero URL/file-reference loading, grants, model/tool calls, jobs, actors or source changes in I04a.

Provider tests must also cover prompt injection, invalid/oversized/truncated replies, denied processing, duplicate ownership, timeouts, unknown spend, interrupted publication and no automatic retry. A later actual live check requires real configuration and must report its limits. Human usefulness, real demand, source authenticity, research validity and investor/consumer outcomes cannot be fabricated to fill missing inputs.
