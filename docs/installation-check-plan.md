# Local installation preflight plan

Next narrow slice after 0.19.0: U16, supporting the requested installable terminal and web workflow. Add a read-only `redteam doctor` preflight and explicit capability/scope limits. This does not enable external apps, actor hierarchy, live providers, or validated stakeholder predictions.

Checks should cover the supported Node range, trusted package metadata/assets, browser-driver metadata, exact headless browser candidate availability, and the workspace directory boundary without creating stores or running an app/model/browser. Do not read `.env`, credentials, sessions, research/vault content, SQLite records, raw project code, or provider keys. Do not repair or install anything automatically. Running the CLI still requires a Node version that can load its native modules; a pure version check is not evidence of compatibility with an older unsupported runtime.

Inspect the pinned local Playwright implementation before choosing browser discovery. `chromium.executablePath()` alone may refer to the full Chromium build, while the runner installs/launches the headless shell. Mirror the actual pinned launch selection, respect an explicit `PLAYWRIGHT_BROWSERS_PATH` without dumping environment values, and distinguish a missing candidate from an executable/file preflight and an actual successful launch. The macOS Chrome fallback is used only after a pinned executable-missing launch error; metadata presence cannot guarantee that fallback or browser startup succeeds. Keep runtime smoke tests separate.

Use bounded metadata reads and safe path/type checks. Report concrete unavailable/unsupported/unsafe states and precise next actions, without source/credential content or raw OS errors. A fresh workspace tree must remain unchanged. Package/source modes and installed archive behavior must both be verified. Browser/platform/permission/asset conditions should be meaningful authored filesystem fixtures, not mocked claims of a real launch. Installed local fixture smoke evidence remains the actual runtime check.

Expose current product scope plainly: one controlled local signup journey, bounded code snapshots and unreviewed notes, supplied action/experiment records, checked comparison/export, scripted/mock-verified actor mechanics, and missing real research/live-provider/pilot/production-isolation/commercial gates. Never infer psychology, population validity, purchase demand, investment decisions, or funding probability from installation readiness.
