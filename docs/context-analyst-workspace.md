# Internal context run bridge

`runContextAnalystInWorkspace(workspace, selection, options?)` joins an explicit input selection to the existing context coordinator. It is an internal library function. This slice adds no terminal start command, API route or web execution control.

`selectContextStartInput(arguments, configuration, readSelectedValue)` requires exactly `CONFIG_FILE --key-env ENV_NAME`. It validates a bounded file argument, a strict environment-variable name and the separate context-v2 configuration before calling the supplied synchronous reader once. It does not read `process.env`, open the configuration file or choose a provider key by default. The reader is trusted application code; tests supply authored values. A rejected native Promise from a mistaken asynchronous reader is observed and denied; asynchronous results are never accepted as keys. The public selection contains no key. A private in-memory map permits one original selection to yield its value once. A serialized or cloned object cannot yield a value. This mechanism avoids accidental serialization; it grants no source rights, ownership or execution authority.

The bridge validates options and cancellation, consumes one original selection, and requires an existing canonical private workspace. A separate read-only preflight rejects unsafe main and sidecar files. It then opens the ordinary writable store and acquires the existing single workspace coordinator slot. A live owner blocks the run. The bridge creates no second ReviewService and performs no browser recovery or job interruption. The slot uses trusted local process IDs; it is not distributed fencing or a separate security principal.

One acquired owner calls the original coordinator once. That coordinator requires exact current brief/context/source/processing bindings, explicit provider/model/rates and separate count/generation caps before dispatch. Existing task, publication, phase accounting and candidate/report rules apply. Failure or cancellation does not authorize another send, new attempt or orphan adoption. Unknown liabilities stay held. No actual local key or provider was used to verify this slice; fake HTTP does not establish native model compatibility.

The writer releases only its acquired owner and closes before report delivery. A failed release or close withholds content. A published result then passes through the existing checked saved-report reader in read-only mode. The report task/run/hash must match the original coordinator. Current rights, file integrity and the caller signal/time window are checked again before the bridge returns. A report changed during writer closure cannot escape as earlier buffered content. A coordinator-unavailable outcome stays unavailable; the bridge does not adopt any diagnostic report left on disk.

Options accept a native AbortSignal and an optional injected fetch for trusted tests. The outer local delivery window allows the configured inference/finalization time plus at most 30000 ms for saved-data inspection. It does not extend the original coordinator deadline, source rights or processing expiry. Cancellation withholds output; a pending read-only inspection may finish its own bounded cleanup before the caller settles. Synchronous SQLite work is not preempted by JavaScript timers. Cross-file/database/clock atomicity, continuous adversarial-local ownership and hard process isolation are not claimed.

Raw or JSON-escaped selected values cannot appear in public configuration/file/name fields, workspace paths or returned data. Values are not printed, written to the session vault or included in manifests. The existing transport suppresses secret-bearing response text. Configuration-file I/O, actual environment selection, process-signal listener lifecycle and user-facing terminal exit codes remain separate integration work.

Successful output is `context_workspace_run_outcome` with `published_unreviewed` status and checked saved report data. Analytical text remains unreviewed, and billing remains the original coordinator's configured-rate record, not an independently authenticated invoice. The bridge adds no app execution, stakeholder decision, researched psychology, purchase/investment prediction, broad news coverage, semantic approval or commercial validation.

Verification uses authored idea/app data and explicit fixture clocks. It covers exact one-use input, active and competing owners, unknown costs/failures, cancellation and late responses, malformed options, forged selections, missing/public workspaces, writer release/close failures, final permission/byte changes, time changes and secret suppression. Full regressions and archive/install evidence are recorded separately in the implementation status.

Installed cold-workspace verification also covers the first metadata/report read after the last writer closes. Empty private SQLite WAL coordination is distinguished from persisted data changes; the existing read-only helpers accept that transition while retaining private sidecar checks and strict main/non-empty-WAL witnesses.
