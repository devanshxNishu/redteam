# Saved context manifests and historical inspection

Version0.45 adds internal exclusive publication and pre-task verification in `src/context-analyst-artifacts.ts`. It saves the exact checked context plan and generation bytes before a future coordinator acquires ownership. It creates no task, ledger, provider request, credential read, result or audit. Saved manifest labels remain the original preparation-time labels; the separate verified envelope records publication checks. Version0.46 adds separate task-bound historical data inspection. Runtime integration remains next. There is no new CLI/API route.

`saveContextAnalystManifest(store, preparation)` requires the actual current in-process preparation from that exact Store, not a copy, serialized flag or reconstructed manifest. It fully checks current declaration, source files, exact generation and frozen plan semantics before creating owner-only `.redteam/context-analyst-runs/RUN_UUID`. It publishes compact canonical `manifest.json` and `generation.json` exclusively, verifies private single-link bytes, and performs complete current validation again. An existing directory or concurrent losing writer fails; no file is replaced, completed by retry, or adopted. Partial or uncertain publication preserves factual orphan bytes without permission or ownership.

`verifySavedContextAnalystManifest(store, preparation)` is a pre-ownership check with the same current preparation requirement. It checks exact pinned hashes and complete file bytes, reconstructs current canonical semantics, re-reads both files and applies final current metadata/deadline guards. It returns immutable checked data with `executionAuthority: not_granted` and `ownership: not_acquired`. A separate in-process receipt is registered only after save succeeds. Verification requires that successful receipt and original preparation, so even complete files left by a failed save cannot be adopted. Restarted processes have no such receipt. The separate task-bound reader described below returns data without rebuilding that receipt. A run UUID alone cannot read/adopt a publication. Revocation, source correction/withdrawal, expiry, elapsed inference deadline, unsafe/missing/changed files or scope mismatch deny delivery.

`checkContextAnalystManifestBytes` in the configuration module copies bounded buffers before awaits, parses strict UTF-8 JSON, normalizes configuration, checks current declaration/source/packet/generation and reconstructs the exact original run/task IDs and preparation/deadlines. Every canonical manifest/generation byte must match the rebuilt plan. It accepts no extra authority fields, changed semantics or alternate formatting. Future preparation times, equal run/task IDs and path-like identities fail. It can validate a historical inference window while current source/declaration rights still permit access. It never registers a preparation capability, saves data, adopts an orphan, slides a deadline or grants execution.

Manifest bytes are bounded to24,000 and generation to500,000; original pretty preparation/generation bounds also remain. Empty and large valid packets keep all selected sources. Source text and references remain untrusted data. Canonical hashes authenticate local consistency only. Private canonical parents, no-follow/single-link file checks and exclusive publication apply; local operator/runtime/clock/DB/filesystem, delivered copies/backups and changes after the final observed read remain boundaries. No atomic transaction across files or independent content-rights/semantic attestation is claimed.


## Task-bound historical inspection, version0.46

`readContextAnalystManifest(store, taskId)` requires an existing private task database in the same workspace. It opens a direct read-only SQLite connection, not a TaskStore constructor. It creates no schema, task or event and repairs no missing store. The reader checks canonical private database/sidecar paths and single-link files before SQLite access. It pins the database device/inode and checks those properties again after reading source files.

The fixed bound query reads at most1,000,000 task-document bytes with strict UTF-8/JSON parsing. The tasks table columns and task spec fields must match the current contract. SQL index columns must agree with the stored spec. The exact task ID, run ID, analyst kind, context question, one-attempt policy, manifest hash and coordinator deadline must match the reconstructed manifest. Task creation must be canonical and fall between preparation and the frozen inference deadline. A run UUID or unregistered orphan directory is insufficient. The trusted local task registry is the historical anchor; this does not retroactively authenticate the process that created its row or recreate a successful-publication receipt.

The reader checks the exact private manifest/generation bytes and fully reconstructs current declaration/source/packet/generation pins through `checkContextAnalystManifestBytes`. It rechecks the pinned task spec/creation time, database identity and both artifact files before delivery. Current source permissions, declaration state and effective expiry remain required. Source correction, withdrawal, revocation, unsafe files and byte or scope changes deny access. Historical inspection can succeed after the original inference/task deadline; it cannot move that deadline or authorize a new request.

The immutable returned envelope is `saved_context_analyst_manifest` version2, with `executionAuthority: not_granted`, `ownership: not_acquired` and `taskStateChanged: false`. It contains checked input data, not an accepted result, task output or operational lease. Existing-owner progress can continue while immutable task pins remain exact. Queued, running or completed states confer no new authority. Returned copies and reconstructed flags cannot pass preparation/publication checks. No ownership claim, task adoption, retry, ledger, credential lookup, model call or public CLI/API route is added.

Node's read-only connection fails when the database does not exist. Extension loading is disabled; a short busy timeout and defensive connection mode apply. SQLite may manage normal sidecar bookkeeping; this is not a promise of zero filesystem activity. Closed-writer database bytes and task/event records are checked for preservation. See the [official Node24.12 SQLite API](https://nodejs.org/download/release/v24.12.0/docs/api/sqlite.html). Local database/operator/clock trust and changes after the final observed check remain boundaries.

Version0.47 adds separate [context-specific fenced ownership](context-analyst-task.md) with original receipt binding and distinct inference/finalization guards. Managed context reads now use an opt-in bounded confirmation for a ctime-only disturbance. The first complete read must retain the same device/inode/link/mode/size/modification time. Exactly one second read anchors to that observed file and must return identical complete bytes with stable ctime. Any additional disturbance, different bytes or data/path/permission/link/identity change fails. Both handles close; there is no write, task or provider-request retry. Mutable inputs and other strict callers retain one-read rejection. Callers still verify canonical expected hashes and current rights. This tolerates observed metadata timestamp churn without claiming uninterrupted file history or an atomic cross-file snapshot.

Context-specific fenced ownership and separate original-handle-bound phase accounting are implemented. Separate bounded context transport is implemented with injected fake fetch.
